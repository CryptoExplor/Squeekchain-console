# PR #4 — gas cleanup

Follow-up to [Phase 4 holder workspace](holder-workspace.md), on the same draft [PR #4](https://github.com/CryptoExplor/Squeekchain-console/pull/4).

## Change

- Removed all four explicit `client.estimateGas` call sites: v6 checkpoint, claim batch and merge; v9's shared action simulator (all approvals, custody, merge, reward, staking and checkpoint actions).
- Removed `gas` from SDK preview objects, nested claim batches and the browser checkpoint result.
- Removed `Gas estimate` detail rows and the `Simulated gas ≈ {gas}` merge-dialog sentence. The wallet remains responsible for network gas and fees; no replacement helper text was added.
- Updated the two tool descriptions that promised gas estimates. Tool names, input schemas, ABI exports and deployment pins are unchanged.
- Kept `simulateContract` at `activeSnapshot.blockNumber`, the final snapshot checks, owner checks, typed BURN and existing fresh post-review preview paths. Nothing signs without the established verified simulation path.
- Kept `quoteUnstake`, the exact SQK `maxFee`, deadline and net amount. `maxFee` inside unstake calldata is **not** an EIP-1559 network fee. v6's remaining `estimate` amount is likewise a SQK claimable amount, not gas.
- `eth_sendTransaction` still forwards **only** `from`, `to`, `data`, `value`. It does not copy transaction objects or forward `gas`, `gasPrice`, `maxFeePerGas`, `maxPriorityFeePerGas`, `chainId` or nonce overrides.

These are not page-load or wallet-internal estimates.

The removed RPC in each case is `eth_estimateGas`. A v6 claim saves **ceil(IDs / 32)** requests per aggregate preview. A normal review plus fresh pre-wallet re-preview saves **two requests per action**, or **two per v6 claim batch**. The checkpoint UI has one preview and saves **one**. A blocked preview that never reached gas estimation previously saves zero. Additional background claim-card refreshes or explicit re-quotes each save their corresponding removed estimates; they are not silently included in the per-action totals. The wallet may still perform its own estimation, outside this application's request accounting.

## Regression coverage

- Both SDK fake clients reject any invocation of `estimateGas`.
- Both actual HTTP responders reject `eth_estimateGas`; every measured successful preview explicitly asserts zero such RPCs.
- Recursive preview checks reject gas/fee fields, including nested v6 batches and the v9 claim wrapper.
- Actual nonpayable `eth_call` simulations in HTTP fixtures are counted and remain snapshot-pinned: one per action, two for a 33-ID v6 claim.
- v9 unstake calldata still decodes to `[amount, exact SQK maxFee, deadline]`, without fee padding; fee-rise, expired-quote and simulation-error regressions are retained.
- Browser workflows cover all v6 actions and all twelve v9 actions, including three new approval cases. Tests deliberately contaminate preview transactions with gas/EIP-1559 fields, drive the normal confirmation path, and assert the mocked `eth_sendTransaction` payload has exactly four keys. Merge/action dialogs are asserted not to contain either removed gas label.
- All wallet requests in these tests use local mocks that reject submission. No real signing, live tests, fork execution, manual deployment or merge.
