        How it works

        Active-profile onchain policy. Merge two same-level Squeeks in the same custody: the donor burns permanently and the survivor keeps its ID and image, gains one level and keeps both Squeeks’ unclaimed SQK. Both must satisfy the active profile’s power and merge-cooldown rules. Maximum level: 10.

        Cooldowns count completed Squeek blocks, not elapsed time.

        Active-profile collection policy
        LevelWeight / powerCooldown (Squeek blocks)

        Checkpoints turn settled rounds into funded SQK rewards for all Squeeks. Any account can checkpoint, pays gas, and receives no caller reward. On v6, owners claim already-funded rewards in batches of up to 32 IDs. On v9, account rewards are claimed through staking, including SQK-only positions.

        Live reward state: Unknown.

        A live Core pause stops checkpoints and new issuance, not claims of already-funded SQK. Runtime reward readiness is shown on Network; an unavailable reading is Unknown, never zero.

        Trust

        Connected Sepolia wallet preferred. Otherwise, browser-direct public RPCs. Every snapshot must match block hashes from two independent RPC peers; mismatch means stop, not a fallback to guessed identities. No server proxy.

        Before each action, we check the network, supported contracts, ownership and permissions using two independent connections. Any mismatch stops the action.
